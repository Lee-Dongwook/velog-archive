프론트엔드 개발을 하면서 UI 변경이나 마이너한 마크업 수정으로 인해 기존 E2E 테스트 코드가 깨지고, 이를 유지보수하는 데 공수가 들어가는 경험을 해보셨을겁니다.

**"테스트 코드의 취약성을 AI 에이전트 구조로 자동화하여 해결할 수는 없을까?"**라는 고민에서 출발해, 최근 학습 중인 기술들을 접목하여 E2E-Self-Heal이라는 작은 프로젝트를 빌드해 보았습니다.

현재 2년차 프론트엔드 개발자로서 실무 환경의 효율화를 목표로 삼았으며, 다음과 같은 구조적 시도를 포함했습니다.

💡 주요 시도 및 구조
자가 치유(Self-Healing) 매커니즘: E2E 테스트 실행 중 UI 변경 등으로 인해 엘리먼트를 찾지 못하거나 에러가 발생했을 때, 실패한 맥락을 파악하고 스스로 대안을 찾아 테스트를 완수하는 흐름을 지향합니다.

LLM 및 에이전트 아키텍처 활용: Python 환경에서 LLM 프롬프팅 및 LangGraph 기반의 Multi-Agent 구조를 실험하며, 테스트 실패 로그와 DOM 상태를 분석하여 수정 행동을 결정하도록 설계하고 있습니다.

거창한 솔루션보다는 '내가 실무에서 마주하는 가려운 부분을 내 손으로 직접 긁어보자'는 목적으로 시작한 프로토타입입니다.

이제 막 기본 구조를 잡고 증명해 나가는 단계인 만큼, 코드나 아키텍처 방향성에 대한 피드백은 언제나 환영합니다. 또한, 컨트리뷰트를 희망하시는 모든 분들도 적극적으로 환영합니다👨‍💻 !
