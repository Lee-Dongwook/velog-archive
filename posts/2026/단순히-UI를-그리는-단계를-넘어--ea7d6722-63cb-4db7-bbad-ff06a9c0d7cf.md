안녕하세요! 이동욱입니다. 프론트엔드 개발 정규직으로 첫 직장에 입사한지 어느덧 1년 반이라는 시간이 지났네요. 처음엔 화면을 구성하고 컴포넌트를 나누는 것만으로도 벅찼던 기억이 나는데, 시간이 흐르며 고민의 층위가 조금씩 달라짐을 느낍니다.

요즘 저는 단순히 UI를 구성하는 것을 넘어 **데이터를 어떻게 시각화하고 관리할 것인가**에 대한 생각의 확장 과정에 놓여 있습니다. 특히 제조 AI와 MES 기반 온톨로지를 다루는 재직 환경에서, 프론트엔드 엔지니어로서 제가 나아가야 할 방향에 대한 정립이 필요하다 느껴 해당 글을 작성해보고자 합니다.

---

### 제조 도메인의 골격: MES, ERP 그리고 온톨로지

제조업의 시스템은 거대합니다. 생산 현장의 실시간 실행을 담당하는 **MES** 와 전사적 자원을 관리하는 **ERP** 에서 프론트엔드는 어떤 데이터를 우선순위에 둘지 결정해야 합니다.

여기에 온톨로지(Ontology)개념이 더해지면 고민은 더 깊어집니다. 설비와 공정 간의 복잡한 관계를 테이블로 보여주는 것은 사용자에게 통찰을 주기가 어렵습니다. 데이터 간의 '의미적 연결'을 파악하고, 이를 지식 그래프 형태로 시각화하여 브라우저에 효율적으로 렌더링할 것인지가 중요하며 사내 팀원들과 협력해야 하는 부분으로 생각이 듭니다.

### RAG의 진화 : Vector에서 Graph로

최근 AI 기술의 흐름을 쫒다 보니 **VectorRAG**와 **GraphRAG**의 차이를 기술하는 문서들을 여럿 본적이 있습니다. 단순히 텍스트 유사도에 의존하는 **VectorRAG**만으로는 제조 현장의 복잡한 인과관계를 설명하기 부족합니다. 데이터 사이의 관계를 타고 들어가 정답을 찾는 **GraphRag**의 논리를 이해하고, 이를 사용자 인터페이스에 어떻게 그려나갈지가 관건입니다.

### 기술적 효율 : SSE와 차세대 UI 도구들

실시간 모니터링이 필수인 제조 대시보드에서 **SSE(Server-Sent Events)** 기술은 하나의 필수적인 선택지가 되었습니다. 단방향으로 쏟아지는 대량의 데이터를 성능 저하 없이 UI에 반영하는 최적의 지점을 찾는 것,

또한, 최근 구글에서 오픈소스화하여 제공한 **A2UI**, 브라우저 DOM없이 텍스트 높이를 측정하는 순수 JS 레이아웃 라이브러리인 **Pretext** 등 도구들의 등장으로 프론트엔드의 작업 방식을 변화하고 있습니다.

**'어떻게 구현할까'** 의 측면도 중요하지만, **'어떤 시스템을 구축할까'** 또한 집중해야 하는 시점임을 느낍니다.

### Claude Code: 에이전틱 워크플로우

최근 개발 생태계의 구조를 변화시키고 있는 핵심 도구 중 하나가 **Claude Code** 같습니다. 터미널 환경에서 프로젝트의 전체 컨텍스트를 이해하고 직접 파일을 수정하거나 테스트를 실행하며, 유저에게 적용 의사를 묻는 일련의 과정을 거치며 개발자의 생산성 향상에 큰 기여를 하고 있습니다.

특히 앞으로 마주하게 될, 제조 도메인의 복잡한 비즈니스 로직에 대응하여, 프론트엔드 개발자로서 로직의 구현에 매몰되지 않고, 전체적인 **'설계'** 와 **'데이터 흐름'** 을 관장하는 아키텍트의 관점을 가질 수 있도록 돕는 강력한 도구가 되어주고 있다 생각하여 활용법을 더욱 숙지해나가고자 합니다.

---

1년 반이라는 시간은 기술 사용법을 익히기에 충분할 수 있으나, 해당 기술로 실 생활에서 어떤 문제를 해결할지 고민하다보니 금방 흘러간 짧은 시간으로 체감되었습니다.

단순히 **보기 좋은 UI** 를 만드는 프론트엔드 개발자에 멈추지 않고, 현 회사에 재직하면서 제조 현장의 복잡한 도메인들을 차근히 이해하고, **Claude Code**와 같은 최신 에이전트 도구를 적극 활용하여 데이터의 진정한 가치를 전달하는 개발자로 성장하고 싶습니다.

#### 용어 정리

- MES (Manufacturing Execution System): 제조 현장의 생산 공정을 실시간으로 관리하고 제어하는 통합 생산 관리 시스템

- ERP (Enterprise Resource Planning): 기업 내의 재무, 인사, 구매 등 경영 자원 전반을 통합 관리하는 시스템

- 온톨로지 (Ontology): 실재하는 사물이나 개념들 사이의 관계를 컴퓨터가 이해할 수 있도록 정의한 지식 모델

- RAG (Retrieval-Augmented Generation): 외부 데이터를 검색하여 AI 모델의 답변 정확도를 높이는 생성 AI 보완 기술

- VectorRAG: 데이터를 벡터(숫자 리스트)로 변환한 뒤, 의미적 유사성에 기반해 관련 정보를 검색하는 방식

- GraphRAG: 데이터 간의 연결 관계(Graph)를 활용해 복잡한 인과관계나 맥락을 추론하며 정보를 검색하는 방식

- SSE (Server-Sent Events): 서버에서 클라이언트로 실시간 데이터를 지속적으로 전송하는 단방향 통신 기술

- A2UI (Agent-to-UI): AI 에이전트가 UI 구성 요소와 데이터를 담은 표준 JSON 메시지를 보내면, 클라이언트가 이를 각 플랫폼에 맞는 네이티브 컴포넌트로 렌더링하는 오픈소스 프로토콜 (https://github.com/google/A2UI)

- Pretext: DOM 리플로우(Reflow)를 유발하지 않고 캔버스 폰트 엔진을 사용하여 텍스트 레이아웃을 계산하는 초고속 오픈소스 텍스트 측정 및 레이아웃 라이브러리 (https://github.com/chenglou/pretext)
